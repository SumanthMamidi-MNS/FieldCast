# Decision log

One line per non-obvious technical choice: what was chosen, and why.

- **2026-09-20 — Pilot region = Maharashtra, held-out transfer test = Karnataka:** a Western Ghats rain-shadow belt gives a ~3000mm→~500mm gradient inside 50km, the strongest real demonstration that block-averaging destroys signal; training on pooled states would leak nearby stations between train and test, so generalisation is proven by transfer instead.
- **2026-09-20 — LightGBM over CNN/GAN super-resolution:** covariates are tabular and ground truth is sparse (neural downscalers need dense fine-scale truth we do not have); LightGBM gives native quantile regression for calibrated uncertainty and stays explainable to the extension officer who must trust the output.
- **2026-09-20 — Predict the local anomaly, not the absolute value:** guarantees the system can only refine the official block forecast, never replace it, so the degenerate failure mode is exactly the naive baseline rather than something worse.
- **2026-09-20 — Two-stage rainfall model (occurrence classifier + conditional amount):** a single regressor smears drizzle across every panchayat, which is the precise false-smoothness failure the core design tension (architecture.md §0) warns about; two stages let one panchayat be dry while its neighbour is wet.
- **2026-09-20 — GHCN-Daily as ground truth:** 3807 real Indian stations are reachable keylessly and give genuine point observations, letting us prove the "beats naive baseline" success criterion on real data instead of only on synthetically coarsened fields.
- **2026-09-20 — Village polygons (datameet) as panchayat proxies:** official panchayat boundaries are not open data at national scale; real village geometry is a defensible approximation and is disclosed as such rather than silently substituted.
- **2026-09-20 — Three-tier output labelling (T1 measured / T2 gauge-validated / T3 inferred):** the honest alternative to presenting extrapolated panchayat-scale numbers with the confidence of validated ones.
- **2026-09-20 — Block-mean reconciliation as a hard post-step:** an agency must be able to stand behind its own published block forecast, so downscaling redistributes within the block rather than contradicting the aggregate.
- **2026-09-20 — Spatial (whole-block) train/test splits, not random row splits:** random splits leak neighbouring grid cells into the test set and would inflate skill scores into meaninglessness.
- **2026-09-21 — Open-Meteo `best_match` ERA5 blend as the T1 fine field, not `era5_land`:** tested live — the `era5_land` model returns null precipitation (daily and hourly) via Open-Meteo, while the blend returns distinct values at ~9 km spacing, so it is the only keyless source with real sub-block rainfall variance.
- **2026-09-21 — Date-level leakage check with a 3-day embargo, replacing the year-level check:** years are too coarse (a legitimate within-year cutoff shares a year but no days), while adjacent days still leak through weather autocorrelation, so the check tests shared dates plus a minimum gap.
- **2026-09-26 — Chi-square-scaled covariate support instead of a fixed 3-sigma cap:** in 7-D a typical training point already sits ~2.6 sigma out, so the fixed cap scored the training data itself as ~0.3 and labelled every panchayat "low"; scaling by the chi-square distribution makes typical terrain high-support and only the tail low.
- **2026-09-26 — Point-scale interval factor fitted on 2022 gauge-days, evaluated on 2023:** the model reproduces ~16 km grid values, so its intervals covered only ~40% of gauge observations; a per-variable widening factor fitted on a season the evaluation never touches restores ~80% coverage out-of-sample and replaces the guessed fixed T3 inflation.
- **2026-09-26 — No "significant" verdict below 8 independent gauges:** a cluster bootstrap over 4 gauges produces an interval that looks precise but is not trustworthy, so the report says "not testable" instead.
- **2026-09-26 — Separate pacing modes (hourly for pipelines, minutely for the API):** hourly pacing made a first map load take ~2 minutes; an interactive request only needs to respect the minutely limit, and a `warm` command pre-computes terrain for demo blocks.
- **2026-09-26 — Frontend: OSM raster basemap, stripes for low confidence, Vite `/api` proxy, lazy-loaded comparison view:** raster tiles need no API key; opacity reads as "smaller value" to non-experts so confidence uses texture; the proxy avoids CORS in development; splitting Recharts out keeps the first load at 62 kB gzipped.
- **2026-09-26 — IMD rainy-day threshold (2.5 mm) for rain occurrence, replacing 0.1 mm:** reanalysis drizzles on ~92% of monsoon days, so 0.1 mm made the model say "rain likely, hold off spraying" for 2 mm; at 2.5 mm the gauge-level occurrence Brier beats the naive block call by 28% and beats climatology, at the cost of rain-amount skill no longer being significant at T1.
- **2026-09-26 — Rainfall reconciled in expectation (sum of P(wet) x amount), not by median:** the block value is a mean and zero-inflated medians sit far below it, so median-matching piled a 1.9 mm block total into one 28 mm panchayat; matching the expectation keeps dry panchayats dry without inflating wet ones.
- **2026-09-26 — T3 support capped at "moderate" with a 0.10 penalty, replacing a 0.25 penalty:** the large penalty labelled every panchayat "low" so the label carried no information; the tier is already disclosed separately, and the cap still guarantees no inferred value is called well-supported.
- **2026-09-27 — AWS Terrain Tiles (terrarium, z11) for all terrain, replacing the Open-Meteo elevation API:** keyless and quota-free, so terrain for every panchayat is precomputable and works offline; validated at 0.9985 correlation (median 2.3 m difference) against the previous source and within ~12 m of known summit/city elevations.
- **2026-09-27 — Orographic profile features (upwind barrier, downwind rise, upwind max elevation along the 245° monsoon flow):** the rain shadow is caused by the ridge upwind of a village, not its local slope, so sampling terrain along the flow line encodes the mechanism directly.
- **2026-09-27 — Natural Earth 10 m coastline for distance-to-coast, replacing a west-coast longitude table:** the table was valid only for the peninsular west coast; the coastline works for any Indian region.
- **2026-09-27 — Deploy on Vercel via the FastAPI preset, not Services or Docker:** the preset is GA and zero-config (`[tool.vercel] entrypoint`), and a StaticFiles mount of the built dashboard is promoted to the CDN, so one app serves locally and in production; Services is a permission-gated beta.
- **2026-09-27 — Numpy-only serving path with a committed serving bundle:** LightGBM, pandas and GeoPandas stay in the local pipeline; the API evaluates flattened trees with numpy (parity with LightGBM to ~1e-15) and reads precomputed terrain, outlines and history, keeping the deployed function at ~83 MB of dependencies against a 500 MB limit.
- **2026-09-27 — Runtime-only base dependencies, training stack as the `pipeline` extra:** Vercel installs `[project] dependencies`, so these must be exactly what the API imports; a test in a fresh interpreter fails if the serving path ever imports a training library.
- **2026-09-27 — Small blocks borrow their 3 nearest grid points:** 6 blocks fell between ~16 km grid points and were silently unserved; they now use their nearest points for terrain statistics, live forecasts and replay history, so every block with villages is served.
- **2026-09-27 — Every map variable coloured relative to the block value, with a per-variable minimum reach:** a fixed wide scale painted a 30.8-32.8 km/h block in one colour; fitting the scale to the block shows the within-block differences the product exists for, and the minimum reach stops rounding noise from being painted as a real difference.
- **2026-09-27 — HTML/CSS whisker chart on the Evidence page instead of Recharts:** lighter, reflows on phones, and a dot-with-CI whisker is all the skill chart needs.
- **2026-09-27 — Replay dates served by the API (`replay_windows`), not hard-coded in the dashboard:** the windows are read from the bundle's history, so the date picker always offers exactly what the API can replay, including dry-season history once fetched.
